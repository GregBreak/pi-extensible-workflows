## Live browser spike and maintenance inventory

`trajectory-browser.test.ts` adds a reproducible browser-only negative feasibility probe using the pinned template and existing Node/CDP harness (no npm dependency). It runs the viewer in `sandbox="allow-scripts"` only (no `allow-same-origin`) with a restrictive CSP: `connect-src 'none'`, no object/base/form, and only inline scripts/styles plus embedded data images/fonts. It transfers a nonce-bound test `MessagePort` without run data. The test was built from the baseline archive and passed in real Chrome.

Observed in that browser:

- The pinned page initializes a static SVG shell with **0 graph nodes** and Finder count 0; it is not a live JSON graph API. The fixture appends, changes a status attribute on, and removes a new SVG node through the private port; the node disappears and camera state remains stable. Local resize and three iframe dispose/reopen cycles work. The isolated viewer issued only the parent and viewer document requests; CSP denies connections and there was no WebSocket.
- The acceptance blocker is reproducible: after the new node is inserted, Archify Finder remains at its captured initial count, returns 0 search results for the new ID, and `Archify.finder.select(newId)` returns `false`. This reproduces the viewer README’s contract: Finder builds a one-time index, exposes no reindex/mount/destroy API, and SVG mutation does not refresh it.
- The checked template is the 774,866-byte generated artifact, not its upstream editable source split. A real live renderer would have to supply SVG before initialization or adapt the viewer lifecycle, then keep Finder/search/selection current while retaining one browsing context. README contracts also identify page-lifetime geometry/camera/layout references in Camera, Reader, and Radar. A source-localized minimal adaptation was therefore not demonstrated. Reworking generated code or replacing Archify’s interaction modules with a handwritten viewer would violate the maintainability/authenticity gate.
- Inventory: retained candidate = full 774,866-byte template; localized upstream patches = 0 bytes / 0 modules; production renderer/adapter = 0 bytes / 0 modules; test-only harness addition = 151 lines; optional advanced viewer features were not split/profiled. The reviewed static input alone is below the 1 MB review threshold, but a feature patch/total profile budget is **unknown**, not presumed to be 10–50 KB. The browser test normalizes Windows CRLF checkout conversion back to this pinned LF input before hashing/serving. No package or HTTP delta for an unimplemented feature is claimed.

This is enough to stop rather than silently relax the gate. The browser proof does not claim that every possible integration is impossible; it establishes that the pinned delivered shell cannot accept the required live graph through its supported viewer API and that we did not prove a localized, maintainable patch. Reconsider only with an owner-approved upstream API/source-maintenance plan or a different pinned viewer. Do not begin E1–E4 on this evidence.

## Pre-feature baseline verification and measurements

All following checks preceded the spike edits to the main checkout.

- `npm ci` on the extracted official baseline: **pass**.
- `npm run check`: first run hit a Windows shell incompatibility at core `test:run` (`files=${TEST_FILES...}` was sent to `cmd.exe`, which reports “files is not recognized”). Retried with Git Bash as npm’s script shell: build, lint, layout tests (3/3), and widget tests (50/50) passed; the full test run failed with environment/baseline issues including Windows process `spawn EFTYPE`, missing `gh`, `spawnSync npm ENOENT`, the existing Trajectory server oversized-reply assertion, and the browser test’s CRLF-sensitive HTML injection assertion. Therefore `check` is **not green**; docs check was not reached.
- Focused compiled Trajectory regressions: 7 files exercised; the export test failed because GitHub CLI `gh` is unavailable, and the server oversized-subagent reply test failed its `assert.ok(current)` condition. The other cases in that focused run completed without reported failures. Browser test file: **3 passed, 1 failed**; the failed test’s fixed LF insertion marker does not match the checked-out CRLF asset. This is a pre-feature test/environment failure, not attributed to Archify.
- New focused E0 test on the official baseline build: `PI_TRAJECTORY_CHROME='C:/Program Files/Google/Chrome/Application/chrome.exe' node --expose-gc --test --test-name-pattern='Pinned Archify E0 sandbox spike' --test-timeout=120000 packages/core/dist/trajectory/test/trajectory-browser.test.js` — **pass**. Focused ESLint on the changed browser test — **pass**. These prove the no-go result only, not an integration.
- Cold official Gantt observation (one Chrome/loopback run, temporary profile): page `document.body.dataset.view === "run"`, swimlane present, no JS exception. `DOMContentLoaded` ≈518 ms and `load` ≈519 ms from navigation start in this capture. Actual `performance` transfer sizes: document 142,275 B, `marked.min.js` 53,169 B, `morphdom.min.js` 12,465 B, `prism.min.js` 23,927 B; `/favicon.png` also requested (1120 B raw). CDP and server both observed the existing single `/ws` upgrade. No Semantic Map URL/request exists on this baseline. This is a local single-run measurement, not a p95.
- `npm run pack:core` (dry-run) passed; correctly treated as file-list reporting, not a tarball. A real `npm pack --workspace=packages/core --pack-destination=...` on the baseline produced a **1,307,374-byte** `.tgz`, **5,974,511 unpacked bytes**, **210 files**. The baseline raw browser assets are 141,975 B HTML, 52,869 B marked, 12,165 B morphdom, 23,627 B Prism, and 1,120 B favicon. Actual tarball inspection confirms three packaged copies of the existing `index.html`: `trajectory/src/assets`, `dist/trajectory/src/assets`, and `dist/trajectory/assets`.
- `npm run test:packages` failed before package verification because the baseline verifier’s `execFileSync("npm", ...)` cannot resolve the Windows `npm.cmd` wrapper as an executable (`spawnSync npm ENOENT`). A fresh actual `npm pack` succeeded and confirmed the test-only fixture is **not** in the package; it reproduced the same tarball size, hash/integrity, unpacked bytes, and 210-file count. This does not substitute for `test:packages`.
